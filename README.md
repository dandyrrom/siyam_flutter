# SIYAM — Animal Sanctuary Management System (Flutter Web)

Role-based web app for managing an animal sanctuary: inventory, medical
treatments, animal records, suppliers, purchases, donations, and reports, plus
a donor-facing portal. It is a Flutter Web port of the original
`Design-SIYAM-Web-Application` React project!

## Current backend: in-memory mock

The app currently runs entirely on an **in-memory mock data layer**
(`lib/mock/mock_database.dart`), seeded at startup. There is no external
backend, database, or secrets required to run it. The data model mirrors the
Postgres schema documented in `[updated_db.md](updated_db.md)`, which is the
single source of truth for what fields/tables exist.

A compile-time toggle (`USE_MOCK`) selects the backend so a Supabase
implementation can be added later without touching the UI (see
[Backend toggle](#backend-toggle)). Supabase is **not implemented yet** — the
non-mock path throws until those services are written.

## Prerequisites

- Flutter SDK on the **stable** channel (Dart `>=3.3.0 <4.0.0`).
- Chrome (the app targets web).

## Backend toggle

The backend is chosen at build time via a `--dart-define`:

```bash
# Mock backend (default — no external dependencies)
flutter run -d chrome --dart-define=USE_MOCK=true

# Supabase backend (NOT implemented yet — will throw at runtime)
flutter run -d chrome --dart-define=USE_MOCK=false
```

The flag is read in `lib/services/backend.dart`:

```dart
const bool kUseMock = bool.fromEnvironment('USE_MOCK', defaultValue: true);
```

Each service is an `abstract interface class` with a factory constructor that
returns either the mock or (future) Supabase implementation. Call sites use the
service normally (e.g. `InventoryService()`), unaware of which backend is
active:

```
InventoryService()            <- abstract interface + factory (picks impl)
  |-- MockInventoryService    <- current in-memory implementation
  `-- SupabaseInventoryService <- Phase 3 (not written yet)
```

Services: `AuthService`, `InventoryService`, `CatalogService`, `PetService`,
`SupplierService`, `DonationService`, `TreatmentService`, `DashboardService`.

## Deploy to Vercel

Flutter Web is static output, so any static host works. Vercel's build image has
no Flutter SDK, so the build happens outside Vercel and the prebuilt `build/web`
is deployed. `vercel.json` provides the SPA rewrite so deep-link refreshes fall
back to `index.html` (the app uses client-side routing via `go_router`).

### CI (recommended)

`.github/workflows/deploy.yml` builds with Flutter and deploys to Vercel on push
to `main` (production) or `feat/supabase-backend-toggle` (preview). Add these
repository secrets:

- `VERCEL_TOKEN` — a Vercel token.
- `VERCEL_ORG_ID` and `VERCEL_PROJECT_ID` — from `vercel link` (written to
`.vercel/project.json`) or the Vercel dashboard.



### Manual (one-off)

```bash
flutter build web --release --dart-define=USE_MOCK=true
cp vercel.json build/web/vercel.json
cd build/web
npx vercel --prod        # framework preset: Other; it deploys the static files
```
